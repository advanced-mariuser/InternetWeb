## Документ по Проектированию: HTTP Веб-сервер

### 1. Обзор Архитектуры

Архитектура системы четко разделена на три логических слоя, каждый из которых имеет свою зону ответственности. Такой подход минимизирует зависимости и способствует созданию модульной системы.

![](uml.png)

**Описание диаграммы:**
*   **Прикладной уровень (`Core`):** `Server` — это ядро приложения. Он выступает в роли "дирижера", координируя работу всех остальных компонентов.
*   **Библиотечный уровень (`http-lib`):** Содержит переиспользуемые модули:
    *   **Модуль HTTP (`Http`):** Инкапсулирует всю логику, связанную с протоколом HTTP. Он ничего не знает о файлах или сети, его задача — только разбирать и собирать текстовые HTTP-сообщения. Включает классы `HttpRequest` и `HttpResponse`.
    *   **Общий модуль (`Common`):** Содержит низкоуровневые утилиты. В данном случае это класс `Socket` — безопасная RAII-обертка для системных сокетов.

### 2. Компоненты Системы

#### 2.1. `Common::Socket`

*   **Назначение:** Полное и безопасное управление жизненным циклом системного сокета.
*   **Ответственность:** Класс `Socket` отвечает **только** за взаимодействие с POSIX Sockets API. Он не знает, какие данные по нему передаются (HTTP, FTP или что-то еще).
*   **Ключевые особенности:**
    *   **RAII:** Гарантирует автоматическое закрытие сокета при выходе объекта из области видимости, что предотвращает утечки ресурсов.
    *   **Обработка ошибок:** Инкапсулирует проверку кодов возврата системных вызовов и преобразует их в исключения C++, делая код на верхнем уровне чище.
    *   **Семантика перемещения:** Позволяет безопасно передавать владение сокетом между потоками.

#### 2.2. `Http::HttpRequest` и `Http::HttpResponse`

*   **Назначение:** Моделирование протокола HTTP.
*   **`HttpRequest`:** Его **единственная ответственность** — разобрать массив символов (`std::vector<char>`) и извлечь из него метод, путь и заголовки.
*   **`HttpResponse`:** Его **единственная ответственность** — собрать ответ из кода состояния, заголовков и тела в единую строку, готовую к отправке.
*   **Инкапсуляция:** Эти классы полностью скрывают детали текстового представления HTTP. Класс `Server` работает с удобными объектами, а не с "магическими" строками.

#### 2.3. `Core::Server`

*   **Назначение:** Управлять жизненным циклом сервера и координировать обработку запросов.
*   **Рефакторинг `HandleClient`:** Изначально этот метод был перегружен. После рефакторинга он стал идеальным примером чистого, высокоуровневого кода. Теперь он только **оркестрирует** вызовы к другим, более специализированным методам:
    1.  `ReadAndParseRequest()`: Отвечает за чтение из сокета и парсинг.
    2.  `GenerateResponseForRequest()`: Содержит основную "бизнес-логику" — поиск файла и формирование ответа (`200 OK` или `404 Not Found`).
    3.  `SendResponse()`: Отвечает за отправку данных в сокет.
*   **Многопоточность:** Принимая новое соединение, `Server` немедленно создает отдельный поток `std::jthread` для его обработки. Это позволяет главному потоку мгновенно вернуться к прослушиванию порта, обеспечивая высокую отзывчивость сервера.
